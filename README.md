# 心语 · HeartEcho

新版本的记忆、互动与独立 TB 版见 [使用说明](docs/NEXT-VERSION.md)。本地开发可运行 `npm run test:next`；Windows 上用 Node 24 执行 `npm run package:tb` 生成独立 TB 便携目录。

[![License: AGPL-3.0](https://img.shields.io/badge/License-AGPL--3.0-blue.svg)](LICENSE)
[![Node](https://img.shields.io/badge/node-%E2%89%A522.5-brightgreen.svg)](package.json)

**一个自托管的 QQ 人格化数字伴侣。** 她有自己的角色、会记住你说过的事、会在合适的时候主动找你，
而你只需要一个控制面板就能把她调成你想要的样子。

这不是"接一个大模型然后随便聊"的机器人。她身上有三件正经事：

| 她做的事 | 怎么做到的 |
| --- | --- |
| **说话像同一个人** | 角色卡按「系统硬约束 → 核心人格 → 关系 → 记忆 → 当前聊天」分层组装，越靠上越改不动 |
| **记得住、也忘得掉** | 短期窗口 + 情景经历 + 事实偏好 + 关系记忆 + 反思，五层分开存，按会话严格隔离 |
| **不会烧你的钱** | 规则前置 → 消息合并 → 冷却限流 → 预算闸门，被拦下的消息**一次模型都不会调** |

```
   QQ 客户端（本机已登录机器人号）
            │  注入
            ▼
   protocol\  ← 心语自带的协议端（SnowLuma），把 QQ 变成标准接口（OneBot 11）
            │  ws://127.0.0.1:3101
            ▼
   心语（本项目）
     ├── 私聊 / 群聊：按角色卡回话，带记忆、带状态
     ├── 数字生命：经历归档、反思、日记、关系演化
     ├── 主动社交：随机搭话、早午晚安、节日生日、事件提醒
     ├── QQ 空间：发说说、点赞评论（能力门控，默认不自动写）
     └── 控制面板 http://127.0.0.1:5311
```

源码仓库和现有打包工具不包含协议端。请自行安装 SnowLuma 或 NapCat，并在「运行环境」里设置协议端目录；配置完成后心语可尝试自动启动它。QQ 客户端也需另行安装并登录。

日常使用就是**双击 `dist\心语.exe`**：不弹命令行窗口、自动连上 QQ、弹一个控制面板窗口、
然后缩进右下角托盘；关掉窗口不会退出，开机也会自动起来。

## 〇、从这个仓库拉下来之后

升级涉及本地面板授权、私人档案的 QQ 绑定和会话清理语义，请先看 [安全边界与升级说明](SECURITY-BOUNDARIES.md)。普通联系人仍可聊天，私人档案仅用于明确绑定用户的私聊。

修改源码前请看 [本地代码检查与格式化](CONTRIBUTING.md)，使用 `npm run lint` 和 `npm run format:check` 检查后端及内嵌前端代码。

仓库里只有**源码和工具链**，下面这些「不属于代码」的东西故意没有提交：

| 没有提交 | 为什么 | 怎么补上 |
| --- | --- | --- |
| `protocol\`（协议端） | 第三方组件，有自己的 EULA，还含 QQ 登录态，~55 MB | 自己装 SnowLuma / NapCat，然后在「运行环境」里把「协议端目录」指过去 |
| `dist\心语.exe` | 90 MB 的打包产物，每次构建都能重现 | `npm i -D esbuild postject` 然后 `node tools/build-exe.mjs` |
| `data\`（含角色卡） | 里面有真实聊天记录、记忆、**API Key**、协议端令牌；角色卡是使用者的创作内容 | 第一次启动自动建目录；角色卡用面板向导新建，或复制 `examples/character.example.json` |
| `build\`、`心语设置.json` | 打包中间文件 / 本机绝对路径 | 见 `心语设置.example.json` |

所以从零跑起来的顺序是：

```powershell
# 1. 需要 Node.js 22.5+（用到 node:sqlite）
node -v

# 2. 自检一下环境（不需要网络、不花模型钱）
node tools/selftest.mjs      # 期望 61 / 61

# 3. 启动（前端面板在 http://127.0.0.1:5311）
node index.mjs --tray

# 4. 打开面板，按向导走：写角色 → 填 API Key → 连 QQ → 填对方 QQ 号
```

> **没有内置 API Key**，**没有内置协议端**，**没有内置角色卡**——这三样都需要你自己准备。
> 想打包成双击即用的单文件：`node tools/build-exe.mjs`。

## 一、三步跑起来

1. **确认 QQ 已登录机器人号**（号在面板「QQ 账号」里填，或点「用协议端当前登录的号」自动读出来）。
   协议端装好后放在 `protocol\`，**不需要你另外启动**——心语会自己检查并拉起它
   （仓库里不带协议端，见上一节）。

2. **启动心语**（挑一个就行）：

   | 方式 | 适合谁 | 怎么用 |
   | --- | --- | --- |
   | **单文件 exe** | 日常使用（推荐） | 双击 `dist\心语.exe`（先用 `node tools/build-exe.mjs` 打出来） |
   | 批处理 | 想看到控制台输出 | 双击 `启动心语.bat` |
   | 命令行 | 开发调试 | `node index.mjs --tray` |

   控制面板地址：<http://127.0.0.1:5311>
   （会缩进右下角托盘，并弹出一个独立的应用窗口——不是浏览器标签页）

   **`dist\` 是一个完整的绿色包**，整个文件夹拷到哪台机器都能用：

   ```
   dist\
   ├── 心语.exe          ← 双击这个（90 MB，自带 Node 运行时，目标机不用装 Node）
   ├── protocol\         ← 协议端（把 QQ 变成 OneBot 接口），需要你自己放进来
   ├── data\             ← 数据目录（第一次启动自动创建；角色卡由向导或你手写）
   └── 心语设置.json     ← exe 的目录设置
   ```

   `心语设置.json` 里用的是**相对路径**（`"dataDir": "data"`、`"snowlumaDir": "protocol"`），
   相对程序目录解析，所以整个 `dist\` 文件夹搬到任何盘、任何路径都还能直接用。

   想换成存在 `%LOCALAPPDATA%\心语` 里，把 `心语设置.json` 的 `dataDir` 清空即可。

3. **照着面板里的向导走**：赋予她真正的心 → 连上大模型 → 连上 QQ → 填对方 QQ 号。
   四步都做完，她就能开始聊天了。

> 首次启动**不会内置任何 Key**（仓库是公开的，硬编码 Key 等于直接泄露）。
> 需要你自己去 DeepSeek / OpenAI 等平台申请一个，粘到「模型与资费」里再点「测试连接」。
> Key 只保存在本机的 `data\config.json`；也可以用环境变量 `HEARTECHO_API_KEY` /
> `DEEPSEEK_API_KEY` 提供，仓库里永远不会有它。
>
> 协议端的访问令牌也是**每台机器各自随机生成**的，第一次启动时写进本机配置，不是公共值。
>
> **连不上 QQ 怎么办**：不用刷新、不用猜。总览页最上面会出现一张红色的
> 「QQ 连不上，先修这一步」卡，上面写清楚了卡在哪一步，并给一个
> 「一键启动协议端」按钮——点它就完事。

### 双击 exe 之后会发生什么

1. **不会弹出命令行窗口**（exe 的 PE 子系统是 GUI，不是控制台程序）。
2. 自动检查并拉起自带的协议端 → 连上 QQ → 弹出控制面板窗口 → 缩进右下角托盘。
3. **第一次运行会自动登记开机自启**（开始菜单的「启动」文件夹里放一个快捷方式）。
   不想要就去「运行环境 → 启动与托盘」把开关关掉，它不会再自己装回来。
4. **关掉面板窗口 ≠ 退出**：窗口只是缩进托盘，机器人在后台继续接收和回复消息。
5. **再双击一次 exe** 不会开出第二个实例，只会把已经在跑的那个面板窗口叫出来。
6. 要彻底停下来：右键托盘图标 →「退出心语（完全停止）」，或者在面板里点「退出心语」。
   退出时会顺便把心语自己拉起来的协议端也停掉，不留后台进程。

### 改机器人 QQ 号 / 对方 QQ 号

面板左侧「系统 → **QQ 账号**」这一页，两个号都在那儿改：

| 字段 | 说明 |
| --- | --- |
| 机器人 QQ 号 | 在 QQ 客户端里已登录、并且能正常收发的那个号 |
| 对方 QQ 号 | 你自己。主动消息、记忆隔离都按这个号算 |
| 对方的称呼 | 她怎么叫你 |

旁边还有「**用协议端当前登录的号**」按钮：直接从协议端读出现在登录的是哪个号并填进来，
省得你自己对数字。右边那张表列出协议端已经接管了哪些号、各自用什么端口。

**换机器人 QQ 号的完整步骤**（面板里也写了）：

1. 在「QQ 账号」填新号 → 保存。心语会顺手给协议端补一份 `config\onebot_<新号>.json`
   （端口和令牌都跟心语对得上），所以你不需要手改配置文件。
2. 在 QQ 客户端里退出旧号、登录新号。
3. 到「运行环境」点「重启协议端」，然后回「QQ 账号」点「用协议端当前登录的号」复核。

### 三种启动方式的区别（选一个看）

**双击 `dist\心语.exe`** —— 最省事，没有控制台窗口。开机自启、托盘、单实例都按上面那样处理。

**双击 `启动心语.bat`** —— 有 exe 时会直接转去启动 exe（不留窗口）；
只有没打包 exe 的时候才会用源码模式跑，那时会显示一个控制台窗口，里面是实时日志，
崩了 5 秒后自动重启。这个文件必须是 **GBK 编码 + CRLF 换行**，改的时候注意。

**命令行** —— 开发用，参数见下表。

### 命令行参数

```powershell
node index.mjs                  # 正常启动（只打印面板地址，不弹窗）
node index.mjs --tray           # 缩进托盘 + 弹应用窗口（推荐日常使用）
node index.mjs --open-panel     # 启动时打开面板，即使设置里关闭了自动打开
node index.mjs --panel-url      # 打印带本机凭据的面板地址；不要分享给他人
node index.mjs --no-panel       # 不弹窗口，只在后台跑
node index.mjs --no-tray        # 不缩托盘（只弹窗口）
node index.mjs --probe          # 自检：配置、角色、模型、QQ 连通性，打印后退出
node index.mjs --archive-now    # 立刻把攒下的对话归档成「经历」
node index.mjs --diary-now      # 立刻写今天的日记
node index.mjs --greet-now      # 立刻让她主动发一条（真的会发出去）
node index.mjs --test-image "D:\图\a.jpg"   # 图片识别自检（不发到 QQ）
node index.mjs --install-autostart          # 装开机自启（进托盘，不弹窗）
node index.mjs --remove-autostart           # 取消开机自启
node index.mjs --autostart-status           # 看当前状态
node index.mjs --desktop-check              # 桌面外壳自检（托盘脚本、图标、开机自启）
```

`dist\心语.exe` 支持**完全相同**的参数，例如 `心语.exe --probe`、`心语.exe --install-autostart`。
（exe 是 GUI 子系统，双击不会有控制台；但被脚本/管道调用时标准输出照常工作，
所以 `心语.exe --probe` 在 PowerShell 里仍然能拿到输出。）

### 自己重新打包 exe

```powershell
node tools/build-exe.mjs                      # → dist\心语.exe
node tools/build-exe.mjs --console-subsystem  # 保留控制台窗口（调试用）
node tools/build-exe.mjs --out "D:\心语.exe"    # 指到别的地方
node tools/exe-verify.mjs                     # 干净机验收（在隔离沙箱里跑，不动你的数据）
```

打包分四步：esbuild 把整个项目打成**一个** JS → Node 的 `--experimental-sea-config`
生成 blob → postject 把 blob 注入一份 `node.exe` → 把 PE 头里的子系统从「控制台」改成「GUI」。
最后一步是「双击不弹命令行窗口」的关键：那个窗口是 Windows 在进程启动**之前**就建好的，
代码里再怎么隐藏都没用，只能改 PE 头。

### 真实端到端测试是怎么跑的

`tools/e2e-live.mjs` 会真的在 QQ 上跑一遍。**仓库里不存任何真实 QQ 号或令牌**，
三个号必须你自己传进去（也可以用环境变量 `E2E_BOT` / `E2E_PEER` / `E2E_PROBE`）：

| 参数 | 说明 |
| --- | --- |
| `--bot` | 机器人号（协议端已接管） |
| `--peer` | 机器人要主动联系的人（你的号，是它的好友） |
| `--probe` | 本机另一个已登录、能主动给机器人发消息的号 |
| `--probe-ws` | 上面那个号自己的 OneBot 地址（默认 `ws://127.0.0.1:3001/`） |
| `--probe-token` | 那个号 OneBot 的 accessToken（没有就留空） |

```powershell
node tools/e2e-live.mjs --bot <机器人QQ> --peer <你的QQ> --probe <另一个已登录的QQ> `
     --probe-ws ws://127.0.0.1:3001/ --probe-token <令牌>
```

**为什么要分 `peer` 和 `probe`**：协议端只能替「本机登录的 QQ 号」发消息。
所以要验证「机器人收到消息 → 按角色回话」这一条方向，发消息的必须是本机另一个已登录号；
而「机器人主动发给某人」这一条方向，可以发给任意好友。
两条方向都测，才是真的端到端。

它会覆盖：私聊双向收发、`记住：…` 与记忆隔离、跨会话检索隔离、决策审计、
模型记账与预算、黑名单闭环（零回复 + 零费用）、解除黑名单、主动消息、面板试聊、空间自检、备份。

## 二、她能做什么

### 0. 天气与位置 —— 到点提醒你带伞

面板「主动 → 天气与位置」。她会：

- **自己知道今天什么天气**：优先用你手填的城市；没填就按公网 IP 猜一个城市级位置
  （不需要系统定位权限，也不上传任何东西）。天气数据来自 Open-Meteo，免费、不用 Key。
- **只在真的值得说的时候才开口**：默认只有 `warn` 级——真下雨、下雪、雷雨、骤降 8℃ 以上、
  35℃ 以上、零下 5℃ 以下、大风。像「可能有零星小雨」「34℃ 有点热」这类只在聊天里顺带提，
  **不会专门发一条**。嫌多可以把这个门槛调高，嫌少就调低。
- **每天最多一次**：默认早上 7:30，错过 150 分钟就不补发了
  ——不然中午突然收到「今天记得带伞」毫无意义。
- **一天只提一次，不再反复念**：只要她当天提过一次（主动发的那条也算），之后的对话里
  提示词会明确告诉她「今天你已经提过天气了，不要再说」。这是「每句话都拐到天气上」的正解。
- **你说一句，她就收手**（重点）：预报只能到市级，一个市里几个区可以完全不一样。所以
  你在 QQ 里说 **「我这边没下雨 / 是大晴天 / 太阳晒死了 / 知道了 / 别再说天气了」**，
  她会立刻：

  1. 把「你那边实际是 X」记下来，当成**比你手上的预报更可信**的事实；
  2. 当天不再主动提天气（默认静默 12 小时，「知道了」算 8 小时）；
  3. 聊天里的天气数据整块撤掉，只留一句「以他说的为准，先认错，别拿预报反驳」。

  万一她这轮还是拐回天气上，会**自动重写一次**（明确禁止出现雨/伞/天气这些词），
  重写还不行就把带天气的句子摘掉——宁可这次少说一句，也不能一边答应一边继续提。

面板上还有一张「**她现在会不会提天气**」卡：显示是否处于静默、静默到什么时候、
她记住的你那边实际情况、今天已提过哪几类，并且有「今天别再提天气 / 恢复提醒」两个按钮
（和 QQ 里说一句改的是同一份状态）。

诚实说明：

- 定位是**城市级**的（按 IP 猜的，可能差几十公里）；想精确就手填城市，
  也可以直接填区名（比如「武昌」），能准一点是一点。
- 预报本身就不保证准。所以整套设计的原则是：**你的观察永远优先于预报**，
  她只是「拿着预报给你提个醒」，不是「坚称今天一定下雨」。
- 需要能访问 `api.open-meteo.com`（以及定位用的 `ipapi.co` / `ip-api.com`）。
  没网、接口挂了、被限流，**只是今天不说天气**，聊天和其它主动消息照常。
- 天气数据超过 6 小时或不是今天的，就当作没有——宁可不说，也不说昨天的天气。

### 1. 对话设置 —— 回多长、回几条、多积极 · 用哪个模型

面板「陪伴 → 对话设置」。三个旋钮各自独立：

| 旋钮 | 含义 | 范围 |
| --- | --- | --- |
| 回复长度 | 单条消息大概多少字 | 60 / 120 / 220，也可以自己填 |
| 最多回复几条 | **上限**，不是必须发这么多 | 1~8 |
| 对话活跃度 | 越高越积极 | 0~100 |

活跃度改的是两件事：

1. **想要几条**：`想要条数 = 1 + (上限-1) × 活跃度`。活跃度 0 就只想要 1 条，拉满才接近上限。
   实际发几条仍然由内容决定——没什么可说的一条就够，不会为了凑数硬拆。
2. **追话概率**：`实际概率 = 设定概率 × 活跃度`。活跃度低就直接不追。
   追话是「她刚回完，隔几秒又补一句」，像真人聊着聊着又想起什么。
   只在私聊里追（群里追等于刷屏），静默时段/暂停/预算超限/被拉黑时一律不追。

页面右侧「现在的效果」会把当前设置算成一句话给你看，不用保存也能预览；改完立刻生效，不用重启。

**同一页还有「她用什么模型跟你聊」**：下拉选模型 → 「用它聊天」即可。换了模型只影响之后的对话，
已有的记忆、角色卡、对话设置都不受影响。旁边有「拉取可用模型」，见下一节。

### 1.5 模型列表与「模型下线」自动纠正

各家 API 的模型名一直在变（Kimi 的 `moonshot-v1-8k` 就已经下线，调用会返回
`404 resource_not_found_error: Not found the model ... or Permission denied`）。
所以这里不靠猜：

- **「拉取可用模型」** 直接请求 `GET {Base URL}/models`，把这家 API 真实给你的模型列出来，
  存在配置里（`availableModels`），下次打开面板直接是下拉列表；
- 「模型与资费」页里**模型字段是下拉**，只有选「手动填写别名字…」才需要自己打；
- **测试连接** 遇到模型不存在时，不再只丢一句原始报错，而是顺手把可用列表摆出来并给出一键切换；
- **对话时也会自动纠正**：如果请求因为「模型不存在」失败，会自己去拉一次列表，
  挑一个通用对话模型换上再重试一次（日志里会写清楚换了什么），
  不会因为一个下线的模型名让整晚的对话全废；
- 顺带处理两个常见的兼容坑：
  - 某些模型（如 Kimi k2.7 系列）**只接受 `temperature = 1`**，传别的值直接 400。
    遇到就自动压成 1 并记住，不再每轮都失败一次；
  - 带思考的模型会把小预算全花在 `reasoning_content` 上、正文为空。现在：
    「模型与资费 → 单次回复上限」可以拉到 **65536**（面板上还有「单次回复上限调到最大」按钮），
    测试连接会自动放大预算再问一次，对话里遇到空正文也会按 ×4 逐级放大重试；
    如果某家模型吃不下这么大的 `max_tokens`，请求会自动降级到它能接受的值并记住，不再反复撞 400。
    这只是**上限**，实际按返回的 token 数计费，不会按上限扣钱。
- 换模型/换服务商时会**一并校正上下文长度、看图能力与价格**——否则换了贵的模型，
  预算还按便宜的价格估，等于没设上限。

### 2. 角色工作室 —— 世界观与「关于你」

面板「陪伴 → 角色工作室」多了两处：

- **世界观**：她生活在怎样的世界（年代、地点、有没有奇幻/科幻设定、社会怎么运作）。
  它会作为独立一层进提示词，排在核心人格之前：她按这个世界的常识说话，但不会向你讲解它。
- **关于你（对方）**：名字、性别、年龄、职业、所在城市、喜欢、不喜欢/忌口、雷区、其他。
  她会把这些当成「早就知道的事」，不会每次问「你是谁」。留空也能用，只是她了解得更少。

提示词的完整分层现在是：

```
系统硬约束 → 世界观 → 角色核心人格 → 关于你 → 人际关系 → 边界 → 说话示例
           → 关系与场合 → 今天真实天气 → 记忆与经历 → 聊天要求（长度/条数/活跃度）
```

「预览最终提示词」现在会真的把这一整段拼出来给你看（带一个小面板告诉你哪几层有内容），
不再是写死的示意图。

### 3. 角色工作室 —— 把她写成你想要的样子（角色卡本身）

面板「角色工作室」里有十二个字段：她是谁、外貌、性格、**说话风格**、行为习惯、人际关系、
边界与底线、第一句话、说话示例、补充设定……

写得越像人话，她演得越准。特别是「说话风格」和「说话示例」——这两项对观感的提升最大。

**锁定字段**：勾上之后，聊天内容、群消息、模型推断都无法改动这些字段。
这是防止"人设漂移"的硬保障，也是防提示词注入的第一道墙。

可以新建多个角色卡，一个角色一个 JSON 文件（`data/characters/` 下），可以直接备份、分享。

### 4. 记忆 —— 记得住，也随时能删

记忆分五类，各管一件事：

| 类型 | 例子 | 特性 |
| --- | --- | --- |
| 情景经历 | "他说周五要去面试" | 带时间、参与者、来源消息 |
| 事实 | "他在准备考研" | 可更新、可纠正 |
| 偏好 | "他不吃香菜" | 会随时间变化，旧偏好保留可追溯 |
| 约定 | "说好周末一起看那部电影" | 会被跟进 |
| 反思 | "我注意到他最近总是很晚才睡" | 需要多条证据，证据不足不会下结论 |

**最快的记法**：直接在 QQ 里说 `记住：我不吃香菜`，她回你一句就记下了。

**隔离是硬的**：每条记忆都带 `owner_character_id / qq_account_id / scope_type / scope_id`，
检索时先做数据库级强过滤。在 A 群听到的事，B 群绝对查不到；私聊里的事，群里也拿不到。
把作用域传成空的，代码会直接报错——**绝不允许退化成全局检索**。

面板「记忆」页可以搜索、锁定、纠错、删除、手动补录；删除之后她就再也检索不到那条了。

### 5. 数字生命 —— 让她有点像活着

- **动态状态**：心情、精力、社交意愿。由真实交互驱动，随时间自然回落，不会因为一句话就剧变。
- **关系演化**：熟悉度、信任、好感、紧张。每次变化有上限并做滑动平均——不会因为一句夸奖就爱得死去活来。
- **经历归档**：攒够十几条消息后，她会把这段对话压成「一份摘要 + 最多 3 条第一人称的经历」。
- **日记**：每天晚上写一篇 200~300 字的随笔给自己看，第二天聊天时作为"她最近在想什么"参与提示词。
- **自我反思**：从多条经历里概括出"我注意到……"，必须带证据条数与置信度。

**虚构日常**是单独开关的，且来源会被标记成 `simulated`——她设想的生活永远不会冒充真实互动。

### 6. 群聊与审核 —— 管住群，也管住钱包

- **每个人的态度**：群成员表里给谁都能单独写"态度"和"备注"，这些文字会直接进她的提示词。
- **回复方式**：仅 @ / 每句都参与 / 只回关键词 / 按概率回 / 从不回复，可以逐人设置。
- **屏蔽词状态机**：默认第 1 次警告、第 2 次拉黑（可改成只警告、直接拉黑、只记录）。
  同一群、同一人、同一规则分别计数；**同一条消息重复投递不会重复计数**。
- **三层黑名单**：全局 / 本群 / 单角色。
- **频率闸门**：按人、按群、全局三层，加上最小间隔和"连续回几条就静默"。
- **决策审计**：面板里模拟一条消息，她会不会回、是哪一步拦下的，一目了然。

被黑名单拦下的消息：**出站消息数 = 0，付费模型调用数 = 0**。

### 7. 主动与日程

| 功能 | 说明 |
| --- | --- |
| 随机搭话 | 间隔随机；会拿最近的经历和日记当话头，所以不会每次都是"在干嘛" |
| 早 / 午 / 晚安 | 各设一个时间点，内容留空就让她按当天情况自己写 |
| 节日 & 生日 | 内置公历节日，可以补农历节日的公历日期；同一年同一个节日只发一次 |
| 事件提醒 | 一行一条：时间 + 提醒什么 + 发给谁 + 是否重复。她用**自己的话**提醒你，不是闹钟播报 |

反打扰是默认开着的：静默时段、连续 N 次没人回就停手、刚聊完就跳过、发送失败指数退避。

三种自动化模式：**完全手动 / 待审核 / 有限自动**。默认只会主动做你已经打开的那几件事。

### 8. QQ 空间（默认关闭，能力逐项验证）

说实话：**空间接口受 QQ 版本与账号影响很大**。
所以这里对每个能力单独维护状态：`未验证 / 发现接口 / 接口可用 / 端到端已验证 / 降级 / 已禁用`，
只有**端到端已验证**的能力才允许参与自动执行。

在一台真实账号上实测过的状态（`node tools/qzone-verify.mjs` 可复现）：

| 能力 | 状态 | 怎么验证的 |
| --- | --- | --- |
| 发文字说说 | 端到端已验证 | 发布 → 读回说说列表，确认这条真的在页面上 |
| 发布带图说说 | 端到端已验证 | 上传本地图片发布 → 读回确认 |
| 读自己空间的说说 | 端到端已验证 | 读到真实数据（`total` 会随发布变化：1 → 2 → 删回 1） |
| 评论动态 | 端到端已验证 | 评论前后对比「评论数」，确认真的增加了 |
| 删除说说 | 端到端已验证 | 删除 → 确认已从列表消失 |
| 读好友动态流 | 接口可用 | 拿到数据，但没有稳定的回归样本，不吹成已验证 |
| 给动态点赞 | 接口可用 | 接口返回成功；**但空间接口只在消息里回评论数，没有「我赞过没有」这个字段，所以点赞状态读不回来**，只能停在这一级 |

- 发说说默认只生成草稿，你点了「发布」才真的发。
- 发完之后会去读一次自己的空间：读到了才标成「已确认生效」，读不到就老实停在「已发出，待核验」。
- 点赞评论用 `tid + 动作` 做幂等键，同一条动态只处理一次，不会重复刷屏。
- **一个实测到的坑**：腾讯对「短时间连续发说说」有节流，连发两条可能只留下最后一条。
  `tools/qzone-interact-verify.mjs` 里因此加了冷却，别在几分钟内连着发。

### 9. 插件与技能（扩展）

心语内置了一套扩展系统：16 个「插件 / 技能」包（来自公开的 QQ Agent 0.4 生态，已适配心语），
在面板左侧 **「插件与技能」** 页可以逐个开关、改设置，停用/启用即时生效。

- **插件**提供确定性能力：群友好感度、连发合并、上下文插话判定、跨会话认人、群友花费统计、自己上网。
- **技能**给模型注册工具 + 提示词片段：小本本（人情账）、去 AI 味、表情品味、回复配图、智能配图、
  搜图、QQ 空间、空间与资料、API 余额乞讨、网页/B 站/RSS 读取。
- 模型可以自己调用这些工具（function calling）；页面顶部有总开关和「一轮最多几轮工具调用」。
- 扩展的网络只能走宿主统一的 `api.fetch`（内网/本机地址会被拒、8 MB 上限），发送只能走
  `ctx.sender`（与正常回复共用出站表与发送前检查），数据只写 `data/extensions/<id>/`。

完整说明（每个扩展做什么、默认开关、目录结构、怎么写新扩展、来源与许可）见
[`EXTENSIONS.md`](EXTENSIONS.md)。**注意**：原始扩展素材没有附带许可证，公开分发前请先
确认各作者的授权（细节见 EXTENSIONS.md 第六节）。

## 三、钱是怎么被守住的

这是最容易失控的地方，所以做了四道闸门：

```
消息进来
  → ① 规则前置：黑名单 / 屏蔽词 / 群拒绝名单      命中就直接结束，0 次模型调用
  → ② 消息合并：同一个群 8 秒内的连续消息合成一次   100 条刷屏只回 1 次
  → ③ 冷却与限流：按人 / 按群 / 全局的令牌桶        超了就安静，自动恢复
  → ④ 预算闸门：调用前「原子预留」，调用后按实际用量对账
```

关键细节：

- **预留是原子的**：并发场景也不会突破你设的硬额度；`达到 80% 预警，100% 熔断`。
- **账单区分来源**：模型返回了 usage 就是 `actual`，没返回就按价格估算并标成 `estimated`。
- **不同任务可以用不同模型**：聊天用便宜的、反思用好一点的，在「模型与资费」里分别指定。

规划书里的容量模型：1000 条/天 → 规则拦掉 70% → 剩下的合并压缩 20% → 实际调用约 240 次。
这个数字只是容量估算，真实值看面板里的账单页。

## 四、安全与隐私

- **只监听本机**：控制面板默认绑 `127.0.0.1`，不暴露到公网。
- **密钥不出现在任何地方**：接口返回的配置里 API Key 一律打码；日志、审计、错误信息全部脱敏。
  密钥只存在你自己的 `data/config.json` 里。
- **信任边界明确**：外部 QQ 消息、空间正文、联系人昵称都是**低信任数据**。
  它们只参与语义理解，不能成为系统指令。"清空全部黑名单"这种话改不了任何配置——有测试用例专门盯这个。
- **数据都是你的**：聊天记录、记忆、账单全在本机 `data/` 目录下，只有你选中的片段会发给你配置的模型服务商。
- **数据目录随便挪**：程序目录与数据目录分开，整个 `data/` 拷到别的盘照样能跑。

## 六、出问题了先看这里

| 现象 | 原因 / 处理 |
| --- | --- |
| 面板左上角显示"QQ 未连接" | **不用刷新，看总览页最上面那张红色的「QQ 连不上，先修这一步」卡**，点「一键启动协议端」就行。它会把卡在哪一步、该点哪个按钮都说清楚 |
| 协议端到底是什么 | 它是一个独立程序，把 QQ 客户端变成标准接口（OneBot）。心语自带一份在 `protocol\`，心语启动时会自动检查并拉起，所以正常情况下你不需要管它。 |
| 想换成自己装的 NapCat | 「运行环境」页把「协议端目录」改成 NapCat 的位置，WebSocket 地址按它的实际端口填。 |
| 她回了句"模型接口报错" | 「模型与资费」页检查 Key / 模型名 / 余额，点「测试连接」看具体报错 |

| 报 `invalid temperature: only 1 is allowed` | 这家模型只吃 `temperature = 1`。点一次「测试连接」或发一条消息，它会自动把温度改成 1 并记住 |
| 面板打不开 | 端口被占：改 `心语设置.json` 里的 `panelPort`；或者上一个实例没关干净 |
| 提示"心语已经在运行了" | 同一个**数据目录**只能跑一个实例（不同数据目录互不影响）。关掉旧窗口，或结束任务管理器里的 node.exe / 心语.exe |

| 双击 `心语.exe` 没反应 | 看 `%LOCALAPPDATA%\心语\logs\` 或 exe 同级目录的日志；也可以先在命令行跑 `心语.exe --probe` 看输出 |
| 双击 exe 弹出一个黑色命令行窗口 | 那是 exe 的 PE 子系统还是「控制台」版。重新跑 `node tools/build-exe.mjs`（默认会改成 GUI），别加 `--console-subsystem` |
| 开机自启没生效 | 「运行环境 → 启动与托盘」看开关是不是开着；也可以看「任务管理器 → 启动应用」里有没有 `心语机器人`。手动装：`心语.exe --install-autostart` |

| 换了机器人 QQ 号但没反应 | 三个地方要一致：「QQ 账号」里的号、QQ 客户端里登录的号、协议端有没有这个号的配置。按面板上「换机器人 QQ 号要三步」走一遍 |

| 点赞一直显示"已发出，待核验" | 空间接口不返回「我赞过没有」，所以点赞状态本来就读不回来——这是如实标注，不是失败 |
| 想让她别回群里 | 「群聊与审核」里把成员的回复方式改成「从不回复」，或直接拉黑 |
| 天气页显示「现在没拿到天气」 | 多半是网络到不了 `api.open-meteo.com`（或被限流）。填个城市再点「只刷新天气」；实在不行不影响聊天，只是她不知道天气 |
| 她老是提天气 / 预报说下雨但我这边是大晴天 | 直接在 QQ 里说一句「我这边是大晴天」「别再说天气了」，她会立刻收手并记住你那边的情况；也可以到「天气与位置」点「今天别再提天气」。想从根上少受打扰就把「到什么程度才值得专门发一条」调成只发 `warn` 级（默认就是） |

| 她收到了但就是不回 | 看「群聊与审核 → 决策审计」，每一条没回的消息都有原因（限流 / 暂停 / 黑名单 / 静默时段…）。主人自己的私聊现在不做限流，真正的刹车是预算 |
| 定位到了别的城市 | 按 IP 猜的，VPN / 代理 / 运营商出口都会影响。到「天气与位置」手填城市，填了就不会再用 IP |
| 她一次只回一句、显得冷淡 | 「对话设置」把活跃度拉高，并把「最多回复几条」调到 3~5 |
| 她明明能多说却只发一条 | 这是设计：条数是上限不是配额，没内容就不硬拆。想更活跃就把活跃度调高 |
| 她每条回复末尾都带同一个表情 | 「聊天参数」里的「允许使用 emoji」关掉 |
| 托盘没有图标 / 双击 exe 没反应 | 看 `data/logs/tray.log` 与 `heartecho-日期.log`，里面写了卡在哪一步。`心语.exe --desktop-check` 会逐项自检 |
| 开机自启没生效 | 到「任务管理器 → 启动应用」看有没有 `心语机器人`；没有就再跑一次 `--install-autostart` |

**出问题时最有用的一句话**：把面板「日志」页的内容，或者 `data/logs/heartecho-日期.log`，
发给 AI 看——里面写清了每一步在做什么、哪一步失败了。

## 七、技术上要注意的几件事

- **协议端已经内置**：`protocol\` 就是 SnowLuma 本体（无 npm 依赖，原生模块走 `process.dlopen`）。
  它用 `path.join(process.cwd(), ...)` 定位 `config` / `data`，所以心语用 `cwd = protocol\` 启动它即可。
  启动逻辑在 `lib/protocol.mjs`：先探端口 → 不在就后台拉起 → 等端口真正能连上才算成功。
- **协议端是第三方组件**：本项目不修改它的代码，也不改变它与 QQ 的对接方式；
  它的许可与再分发限制以它自带的 `EULA.md` / `PRIVACY.md` 为准。
- **消息至少一次投递**：所有写入都按 `event_key` 做幂等，重复投递不会产生第二条回复、不会重复计数。
- **发送状态未知 ≠ 失败**：这种情况进 `unknown` 待核验，绝不盲目重发。
- **中文检索**：FTS5 对中文分词不友好，所以用「二元分词倒排表 + LIKE 兜底」保证召回，
  但**权限过滤永远先做**——向量或全文检索都不能替代作用域过滤。
- **前端是拼字符串生成的**：改 `lib/ui-app.mjs` 里的模板时，注意 HTML 属性里的引号不要和 JS 字符串的引号打架。
  改完跑 `node tools/check-ui-template.mjs` 和 `node tools/smoke.mjs` 会直接告诉你有没有问题。
- **bat 编码约定**：`启动心语.bat` 必须是 GBK(936) + CRLF。存成 UTF-8 或 LF 会乱码
  （双击后窗口一闪就没了，或者满屏"不是内部或外部命令"）。
- **托盘脚本必须带 UTF-8 BOM**：`lib/desktop.mjs` 生成 `tray.ps1` 时会加 BOM。
  Windows PowerShell 5 读无 BOM 的 `.ps1` 会按 ANSI(GBK) 解码，脚本里的中文注释会变乱码并把解析器带崩
  （报一堆莫名其妙的语法错）。`node index.mjs --desktop-check` 会解析一遍脚本，改坏了立刻能发现。
- **单实例锁按数据目录加锁**：锁文件名是数据目录路径的哈希，所以不同数据目录可以各跑一个实例
  （正式数据 + 测试沙箱互不干扰），但同一个数据目录绝不会跑出两个。
- **备份用 `VACUUM INTO`**：它会产出一份**自包含**的数据库文件，不需要额外拷 `-wal` / `-shm`。
  靠「checkpoint + copyFile」是不牢靠的——只要还有别的连接持有读快照，WAL 就合并不干净，备份会少一截。
  这是「备份看起来成功、恢复后少了数据」的经典坑，`tools/backup-verify.mjs` 会真的做一次恢复演练来兜住它。
- **打包时的 `import.meta.url`**：esbuild 转成 CJS 后这个值不可靠，所以打包脚本会注入
  `globalThis.__HEARTECHO_BUNDLED__ = true`，`paths.mjs` 优先看它来决定程序目录。
- **exe 必须改成 GUI 子系统**：`node.exe` 是控制台程序，双击会带一个黑窗口，而且那个窗口是
  Windows 在进程启动前就建好的，代码里藏不掉。所以打包脚本会改 PE 头里的 `Subsystem` 字段（3→2）。
  偏移是可选头 + 68（PE32 和 PE32+ 都是 68；+72 是 `Win32VersionValue`，写那里等于没改）。
  副作用是双击时没有控制台输出，但被管道调用时 stdout 照常工作。
- **不能自己 spawn 一个 helper 去「重启自己」**：实测父进程一退出，子进程（powershell / wscript，
  连 `detached` 也一样）会跟着一起死，helper 根本来不及把新实例拉起来。
  所以 `relaunchSelf` 走 `explorer.exe <exe>`——由系统外壳启动，新进程的父进程是 explorer，
  和我们没有父子关系。新实例靠「锁还在但面板端口不在」判断是重启，会等老实例退出再接管。
- **消息宁可多记一笔，也不能凭空消失**。三层保障：
  ① 进来的消息**先入库再过闸门**——被限流/被暂停/在黑名单里的消息也会留在对话记录里，
     面板上能看见，决策审计里有原因（以前是先判定、不回就不记，用户看到的就是「她没收到」）；
  ② 同一会话上一轮还没生成完时，新消息**排队合并**，不丢（以前是直接 `busy` 返回）；
  ③ 连上协议端时调 `get_friend_msg_history` **补一遍**最近的私聊历史，把库里没有的补进来
     （协议端断线那几秒、心语重启/关机期间对方发的消息，靠这个补回来）。
     event_key 是 `private:<self>:<message_id>`，所以反复补也不会写重复。
     补回来的**不会触发回复**——它们是几分钟甚至几小时前的消息，回了才奇怪。

「消息收不到」这条修复的验证方式：**在心语没运行的时候**用另一个号发两条消息（协议端还开着，
它照样在收），然后启动心语——两条都被自动补进对话记录；再点一次「补回漏掉的消息」，
条数不变（重复补不会写两遍）。

同时查清了这次「时不时收不到」的真实原因是**每小时 30 条的频率上限**：
日志里明写着 6 条 `silent · 这一小时已经聊了不少了（30/30）`，而那 6 条在库里根本不存在。
修完之后：主人私聊不再限流、被拦的消息也会入库、连发会排队合并、断线期间的会补回来。

天气「说过了还一直说」这条修复，是在真实 QQ 上一条条对话验的：

| 步骤 | 她的实际回复 |
| --- | --- |
| 我说「今天天气怎么样呀」 | 「预报说阵雨，不过你那边是大晴天，那初月就不提雨了」 |
| 我说「我这边没下雨啊，是大晴天，太阳晒死了」 | 「好啦好啦，初月记住啦，你那边是大晴天，太阳很晒呢。是不是刚在太阳底下站了一会儿呀？」 |
| 我说「知道了」 | 「嗯，那初月就不啰嗦啦」 |
| 我换话题「我下午要去公司一趟」 | 「不想动的话，就先从换衣服开始吧……」——**回复里没有任何雨/伞/天气** |

同时验到并修掉的连带问题：

- 私聊里「15 秒最小间隔」会直接丢掉你连发的第二条（那句「我这边是大晴天」曾被丢掉，
  所以她永远学不会，只能一直重复）→ 该规则现在只管群聊。
- 「连续回 8 条就静默 20 分钟」会在聊得正热时让她突然不理人 → 同样只管群聊，
  私聊的交给她每小时的硬上限。

三点如实说明：

- **点赞止于「接口可用」**：空间接口返回的说说字段里没有「我赞过没有」，
  所以点赞状态读不回来，面板上会如实显示成「已发出，待核验」，不假装验证过。
- **托盘的实际鼠标交互**没法自动测：自检能证明脚本语法正确、进程起得来、
  日志写了「托盘已就绪」，但双击弹窗口、右键菜单要点一下才算真验过。
- **定位只能到城市级**：没有系统定位权限，是按公网 IP 猜的（可能差几十公里）。
  想准就手填城市；填了城市之后 IP 就不再参与，也不会再动。

### e2e 会临时放宽频率闸门、关掉追话（跑完恢复）

`tools/e2e-live.mjs` 会在几分钟内连发十几条消息，很容易把真实账号的
「每人每小时 30 条」额度烧光，然后整轮假失败。所以它开跑前会**临时把限流放宽**，
结束前**恢复你原本的设置**（E2E-08b 会明确报告这一步）。

同理，**追话是按概率触发的**，会让「这一轮新增几条消息」的断言偶发失败，
所以 e2e 也会临时把追话关掉、跑完恢复。测的是功能，不是概率本身。

另外「对方回话」的判定以**机器人自己的对话记录**为准，不只是靠 WebSocket 收——
因为测试为了替对方发消息开了第二个 OneBot 连接，协议端不保证把事件推给每一条连接。
