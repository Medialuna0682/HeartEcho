## 1. 目标与范围

### 1.1 本次目标

1. **修复四个阻塞问题**（§5）：bat 不弹面板、新建角色静默覆盖/失败、TB 首启退出循环、SnowLuma 未内置。
2. **改造运行时架构为 A2**：安装版 = 小启动器 + `runtime\node.exe` + `app\` 源码；目标机无需安装 Node。
3. **两个一键安装包**：泛用版与领航员终端（TB）版；内置干净 SnowLuma（`protocol\`），自动启动/停止/诊断。
4. **安装体验**：per-user 免管理员；桌面/开始菜单快捷方式；默认开机自启（弹窗说明，可关）；卸载可保留/删除数据；覆盖安装保留数据。
5. **文档与许可**：安装说明、首次使用、SnowLuma 登录说明、许可与来源、卸载/迁移/排障；README 修正。

### 1.2 非目标

- 自动登录 QQ（SnowLuma 依赖本机 QQNT 客户端已登录，扫码只能人工）；
- 内置模型 API Key / 角色卡 / 聊天数据；
- 公开商业分发（A1 限小范围非商业）；SnowLuma 再分发范围按 EULA 与用户确认执行；
- 自动更新、代码签名、Windows 服务化安装、macOS/Linux；
- 自动申请/购买模型额度。

## 2. 目标架构（方案 A2：单运行时）

### 2.1 安装目录与数据目录

**泛用版**

```
%LOCALAPPDATA%\Programs\HeartEcho\        ← 程序（per-user，可写）
├── 心语.exe                                  ← 小启动器（C#，几十 KB；负责注入环境并拉起 node）
├── app\                                      ← 源码运行负载
│   ├── index.mjs
│   ├── lib\                                  ← 全部后端模块
│   ├── extensions\                           ← 16 个扩展 + extensions/src 兼容层
│   ├── package.json                          ← 必须（"type": "module"，扩展也依赖）
│   ├── docs\  EXTENSIONS.md  LICENSE  NOTICE  VERSION.json
├── runtime\node.exe                          ← Node 24（项目/协议端共用；附 Node 许可证）
├── protocol\                                 ← 干净 SnowLuma（安装器首次写入；可写）
│   ├── index.mjs / *.js / client\ / native\ / QQNT\ / EULA.md / PRIVACY.md
│   ├── config\（运行时生成：onebot_<QQ>.json、runtime.json、webui.json）
│   ├── data\ / logs\（运行时生成）
├── 心语设置.json                             ← {"dataDir":"", "snowlumaDir":"protocol", ...}
├── 卸载.exe
└── 第三方许可\

%LOCALAPPDATA%\心语\                        ← 用户数据（程序目录之外）
├── config.json / characters\ / database\ / extensions\ / logs\ / backups\ / cache\ / media\ / state\
```

**领航员终端（TB）**

```
%LOCALAPPDATA%\Programs\NavigatorTerminal\  ← 建议英文目录名，显示名「领航员终端」
├── 领航员终端.exe                            ← 启动器（固定带 --tb + 安装模式标记）
├── app\  runtime\node.exe  protocol\（WebUI 端口预设 5098）
├── 心语TB设置.json / 卸载.exe / 第三方许可\
%LOCALAPPDATA%\心语TB\                      ← 数据（沿用现有 boot-env 路径，兼容旧数据）
```

说明：

- 显示名/安装包/快捷方式用「领航员终端」；**内部数据路径继续用 `心语TB`**，避免 `boot-env.mjs` 重写与旧数据迁移；如需彻底改名，另立任务。
- 若用户坚持安装到 `C:\Program Files`：安装器必须把 `protocol\` 放到 `%LOCALAPPDATA%\心语\runtime\protocol`，并把绝对路径写进 `心语TB设置.json`/`心语设置.json`，否则 SnowLuma 无法写配置/数据。默认为 per-user 安装即可规避。
- 升级：只覆盖 `app\` 与 `runtime\` 代码文件；`protocol\config|data|logs` 与 `%LOCALAPPDATA%` 用户数据不动；升级前自动备份 DB。

### 2.2 启动器职责（新增，C#）

启动器 `心语.exe` / `领航员终端.exe`（用 `csc /target:winexe` 编译，图标 `build\app.ico`，不弹控制台）：

1. 计算安装根目录（自身所在目录）；
2. 设置环境变量：
   - `HEARTECHO_APP_DIR=<安装根>`
   - `HEARTECHO_INSTALLED=1`（v1.3.0 新增安装模式标记）
   - `HEARTECHO_EDITION=tb`（仅领航员终端）
3. 以 `runtime\node.exe app\index.mjs --tray` 启动（TB 追加 `--tb`；用户自定义参数原样转发）；
4. 工作目录 = 安装根；等待进程退出并透传退出码（重启场景由 app 的 `relaunchSelf` 处理，或启动器检测退出码 42 后重新拉起）；
5. 单实例/已运行时：app 自己会发现锁并打开面板，启动器无需额外处理（可选：若 app 快速退出且面板端口在监听，直接 `Start http://127.0.0.1:<port>`——建议实现，体验更好）。

> 启动器只做壳，**业务逻辑仍全部在 index.mjs**；不要在里面复制路径/配置逻辑。

### 2.3 应用侧为 A2 必须做的适配

| 主题 | 现状 | A2 改造 |
| --- | --- | --- |
| 安装模式判定 | `isSea` / `HEARTECHO_BUNDLED` | 新增 `HEARTECHO_INSTALLED=1` 判定；`paths.mjs` 导出 `isInstalled` |
| 默认数据目录 | SEA：`%LOCALAPPDATA%\心语`；源码：`<APP_DIR>\data` | 安装模式默认 `%LOCALAPPDATA%\心语`（TB 为 `%LOCALAPPDATA%\心语TB`）；也可由安装器写设置 `dataDir` 双保险 |
| 桌面形态 | `desktopMode = TRAY || isSea` | `desktopMode = TRAY || isSea || isInstalled`（或启动器固定传 `--tray`，两者都做更稳） |
| 开机自启 | 仅 `isSea` 首次自动登记 | 由**安装器负责**（默认勾选+弹窗说明）；应用面板“开关”改为调用安装模式的自启逻辑；避免首次启动重复登记/覆盖用户选择 |
| 重启自己 | SEA 走 explorer；源码走 `node index.mjs --takeover` | 安装模式优先重启**启动器**（带 `--takeover`）；若拿不到启动器路径，退回 `process.execPath` + `app\index.mjs --takeover` |
| 多实例 | `instancesHome` 默认程序目录；子实例用 `process.execPath` 拉起 | 安装目录 per-user 可写，HOME 仍默认安装根；子实例拉起改为 `runtime\node.exe app\index.mjs --instance ...`（参考现有 `isSea ? args : [SOURCE_ENTRY,...args]`）；确认 `HEARTECHO_INSTALLED` 传递 |
| 协议端 Node | `findNode()` 只找系统 Node | 优先 `<APP_DIR>\runtime\node.exe`、`<APP_DIR>\node.exe`、`<snowluma>\node.exe`，再 fallback 系统 |
| 打包 | `tools/build-exe.mjs`（SEA） | 安装包不再用 SEA；新增 `tools/build-installer.mjs` 组装 A2 payload；`build-exe.mjs` 保留为可选便携产物（是否保留待用户确认，默认保留） |
| TB 版 | `package-tb.mjs` 便携包 | 安装包复用同一 A2 payload，仅启动器/名称/端口/数据目录不同；`package-tb.mjs` 可保留为便携包工具 |

> 关键回归点：源码模式、SEA 便携版（若保留）、安装模式三种形态都要能：开面板、托盘、开机自启、重启、多实例、协议端启动、面板 token 正确。A2 是本任务最大的技术风险，见 §6/§7。

### 2.4 端口与双版本共存

| 项目 | 泛用版 | 领航员终端（TB） |
| --- | --- | --- |
| 安装目录（默认） | `%LOCALAPPDATA%\Programs\HeartEcho` | `%LOCALAPPDATA%\Programs\NavigatorTerminal` |
| 数据目录 | `%LOCALAPPDATA%\心语` | `%LOCALAPPDATA%\心语TB` |
| 控制面板 | 5311 | 5321 |
| OneBot WS / HTTP | 3101 / 3100 | 3103 / 3102 |
| SnowLuma WebUI | 5099（`protocol\config\runtime.json`） | **5098**（安装器写入） |
| 启动器 | 心语.exe | 领航员终端.exe |
| 开机自启名称 | 心语机器人 | 领航员终端 |

规则：

- 两个版本可同时安装，但**不要同时运行**（各自 SnowLuma 会尝试注入同一个 QQ.exe / 抢 WebUI 端口）；应用启动时检测另一版本进程/端口并提示；
- 同一 QQ 号同一时间只能跑一个实例：现有跨进程账号占位 `%LOCALAPPDATA%\HeartEcho\accounts\<QQ>.json` 已覆盖（要求两版都执行检查）；
- 安装器/首启检测端口占用，给出可改端口指引。

## 3. 安装器与构建流水线

### 3.1 安装器（自研 C#，方案 B1）

- 构建机用 Windows 自带 `C:\Windows\Microsoft.NET\Framework64\v4.0.30319\csc.exe` 编译（Win10/11 自带 .NET Framework 4.8；目标机无需额外运行时）；
- 安装器本体几百 KB + **内嵌 ZIP payload**（资源或尾部附加；解压用 `System.IO.Compression`）；
- UI 流程：欢迎/许可（AGPL + SnowLuma EULA/PRIVACY + Node/扩展来源）→ 安装位置（默认 per-user，可改）→ 选项（桌面快捷方式、开始菜单、**开机自启（默认勾选）**）→ 进度 → 完成并启动；
- 快捷方式：WScript.Shell COM 创建 `.lnk`，目标 = 启动器，图标 = `build\app.ico`；
- 卸载：写 HKCU `Software\Microsoft\Windows\CurrentVersion\Uninstall\...`；`卸载.exe`（或安装器 `/uninstall`）停止进程/协议端→删程序文件→询问保留/删除用户数据（默认保留并提示路径）→清快捷方式/自启/注册表；
- 静默安装（供测试）：`/S`（静默）+ `/D=<目录>`（Inno 风格）或 `/silent /dir=...`；退出码：0 成功、非 0 失败原因可读；
- 升级检测：发现旧版本（注册表/版本文件）→ 覆盖安装；发现旧便携版 `dist\data`/仓库 `data` → 询问是否导入数据（复制，不删原数据）；
- 开机自启：默认勾选 + 安装时弹窗说明；不勾选则不建启动项；
- 卸载/升级时检测正在运行的进程与端口（也可复用 PowerShell 命令或 Win32 API），提示先退出。

### 3.2 构建流水线 `tools/build-installer.mjs`

1. `node tools/gen-extensions.mjs`；
2. 组装 `build\installer\payload-<edition>\app\`：复制 `index.mjs`、`lib\`、`extensions\`、`package.json`、`LICENSE`、`NOTICE`、`EXTENSIONS.md`、`docs\`（只带安装/使用/许可类文档；不带任务书）；
3. 复制 `process.execPath`（Node 24）→ `runtime\node.exe`；附 Node 许可证（`package-tb.mjs` 的网络获取或 `HEARTECHO_NODE_LICENSE` 本地文件逻辑可复用）；
4. 调 `tools/prepare-protocol.mjs --protocol <用户提供的干净 SnowLuma 目录> --edition generic|tb` → `protocol\`（清洗、写默认 `runtime.json` 的 `webuiPort`，生成文件清单 SHA-256）；
5. 用 `csc.exe` 编译启动器（`/target:winexe /win32icon:build\app.ico /out:<payload>\心语.exe`，TB 为 `领航员终端.exe`；可把 edition 作为常量或读取安装根标记）；
6. 写 `心语设置.json`（泛用：dataDir 空/绝对、snowlumaDir "protocol"、openPanelOnStart true、autoStartProtocol true）/ TB 设置（snowlumaDir 绝对路径，webuiPort 5098 已写在 protocol）；
7. 生成 `VERSION.json`（版本/构建时间/commit/edition）；
8. 打包 payload 为 ZIP；用 `csc` 编译安装器（内嵌 ZIP + 图标 + 版本资源）；
9. 输出 `dist\installer\心语-安装-vX.Y.Z.exe`、`领航员终端-安装-vX.Y.Z.exe`、`.sha256`；
10. 冒烟：静默安装到临时目录 → 启动 `--probe`/API 健康 → 卸载 → 校验无残留（新增 `tools/installer-smoke.mjs`）。

### 3.3 `tools/prepare-protocol.mjs`（新增）

- 输入：**用户提供的官方干净 SnowLuma 发布包**（不得直接拿运行中的 `dist\protocol`，里面有登录态/消息/日志/webui 密码）；
- 保留：`index.mjs`、`server-*.js`、`config-*.js`、`logger-*.js`、`utils-*.js`、`package.json`、`client\`、`native\`、`QQNT\`、`EULA.md`、`PRIVACY.md`（如官方包有 LICENSE/NOTICE 一并保留）、`data\sys-face-catalog.json`（如需要）；
- 剔除/置空：`config\onebot_*.json`、`config\webui.json`、`config\notifications.json`、`config\webui.json`、`data\<QQ>\*`、`logs\*`、`launcher.bat` 视需要；
- 写默认 `config\runtime.json`：`{webuiHost:"127.0.0.1", webuiPort:5099|5098, hookAutoLoad:true, ...}`；
- 生成 `protocol-manifest.sha256` 供构建/安装校验；构建脚本拒绝包含用户数据的目录（检测 `onebot_*.json`/`data/<数字QQ>` 直接报错）。

### 3.4 交付产物

- `dist\installer\心语-安装-vX.Y.Z.exe` + `.sha256`
- `dist\installer\领航员终端-安装-vX.Y.Z.exe` + `.sha256`
- 可选：`dist\心语.exe`（SEA 便携版，若保留）与 `dist\HeartEcho-TB\`（TB 便携包，若保留）
- 安装包内 `docs\`：安装说明、首次使用、SnowLuma 登录、许可与来源、卸载与迁移。

## 4. 内置 SnowLuma 与登录引导

### 4.1 内置方式（已确认）

- 用户提供官方干净发布包；安装包内置**未修改**运行时；安装器许可页展示并让用户接受 SnowLuma EULA/PRIVACY；
- 应用自动以 `runtime\node.exe` 启动 `protocol\index.mjs`（隐藏窗口，日志落 `<data>\logs\protocol.out.log`）；
- 启动 env：
  - `SNOWLUMA_ACCEPT_EULA=1`、`SNOWLUMA_ACCEPT_PRIVACY=1`（仅在安装时用户已同意）；
  - `SNOWLUMA_WEBUI_BOOTSTRAP_PASSWORD=<安装器生成的随机强密码>`（首次；写入本机设置，面板可查看/复制/修改提示）；
- `findNode()` 优先随包 `runtime\node.exe`；
- 端口：泛用 WebUI 5099、TB 5098；OneBot 端口按应用配置写入 `config\onebot_<QQ>.json`；
- 停止：退出心语时只在“没有其他实例在用”时停协议端（沿用 `protocol.mjs` 现有逻辑）。

### 4.2 QQ 登录（无法自动化，必须讲清楚）

- SnowLuma 通过注入本机 `QQ.exe`（QQNT 客户端）工作；**用户必须自己安装 QQ 客户端并登录机器人号**；安装包不附带 QQ；
- 首次使用引导要显示：
  - 是否检测到 `QQ.exe` 进程/QQ 安装目录；
  - “请打开 QQ 客户端并登录机器人号”；
  - 登录后 SnowLuma 自动 hook，应用检测到 `config\onebot_<selfId>.json` 与 OneBot 端口可连 → 显示“已接管 QQ”；
- 失败分类提示：未装 QQ / QQ 未登录 / QQ 版本不兼容 / 端口占用（附最后 20 行协议端日志）；
- 同一原因只提示一次（去重），不同原因变化时才重新提示；日志原文落盘；
